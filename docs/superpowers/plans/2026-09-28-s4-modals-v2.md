# S4 弹窗统一（公共外壳 + 人员库 5 弹窗 + 外部模型）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 抽出一个公共弹窗外壳 `AppModal`（统一宽度令牌 / 高度策略 / 头部结构 / 关闭钮 / 聚焦），并用它重写人员库 5 弹窗（人员库、人员编辑、内置详情、添加人员、临时添加）+ 成员抽屉内嵌的提示词详情弹窗 + 外部模型弹窗，清偿这些表面的 legacy 规则。

**Architecture:** 继续绞杀式迁移：`AppModal` 只是 `ui/dialog` 原语之上的一层**组合壳**（不复制原语、不改 Radix 行为参数），负责「尺寸 + 头部 + 关闭钮 + 聚焦」四处重复面；各弹窗内部（列表/表单/卡片）的样式逐条从 legacy 翻成 utilities，**行为、id 契约、appState/uiBus 链路、命令流一行不改**。每个弹窗迁移的同一 commit 内删除 legacy.css 里**只被它使用**的规则；共享族（还有 S5/S6 使用者）**不删**，只记录。

**Tech Stack:** React 19 + Tailwind v4（`tw-animate-css`）+ shadcn/ui（new-york / zinc，本地原语在 `src/teamPage/ui/components/ui/`）+ vitest + @testing-library/react + puppeteer 验收脚本。

**Spec:** `docs/superpowers/specs/2026-09-28-shadcn-ui-rebuild-design.md`（§3 令牌与圆角、§4 布局、§6 组件映射表「人员库 5 弹窗 → Dialog/Card/Badge/Empty」、§7.4 阶段表 S4 行、§9:224「弹窗叠层：保持现有『逐层关闭』语义（W1 已实现），重塑不得改 Radix 层级参数以外的行为」）。
**输入台账**：`.superpowers/pending/2026-09-28-modal-inventory.md`（全应用 11+1 主弹窗 + 5 AlertDialog + 2 Sheet 的现状清点与差异清单）、`.superpowers/pending/2026-09-28-s3-handoff.md`（层序、共享族、M-1..M-4 的落点）、`.superpowers/pending/2026-09-28-ui-bugfix-batch.md`（2026-09-28 修复批次，其探针是本阶段的回归门）。

## Global Constraints

- **样式基准**：shadcn 官网（new-york / zinc）。圆角只用 `rounded-md`(8px) / `rounded-lg`(10px) / `rounded-xl`(14px)（`xl` 仅浮窗外壳；菜单/命令项 `rounded-sm` 是官方做法，不算违规）。弹窗内容一律 `rounded-lg`。
- **零新依赖**：不新增任何 npm 包。只用已有原语（dialog / alert-dialog / card / button / badge / input / textarea / empty / tooltip / dropdown-menu / select）。
- **覆盖官方原语**：凡要改官方原语自带的类，**必须**写进该原语的 `className` prop（`cn()` = twMerge，同组后者胜）。禁止「子元素自带类名 + 靠 Tailwind 输出顺序取胜」。
- **正文内边距必须显式接管（T1 评审发现，全阶段适用）**：6 个目标弹窗**没有一个自带 padding**——24px 内边距全部来自原语 `DialogContent` 基类的 `p-6`（已 `grep` 确认；`.modal-form` 只有 `display:grid; gap:12px; margin-top:12px`，`.people-library-content/-pane` 只有 `min-height/overflow`）。`AppModal` 用 `p-0` 收掉它、改由头部自带 `px-6 py-4`，因此**每个迁移的弹窗都必须用 `bodyClassName` 把正文内边距补回来**：一律 `p-6`（左右 24px 与头部 `px-6` 对齐）。漏了就会让正文贴到弹窗边缘，而单测（jsdom 不算布局）**抓不到**，只有 T6 的截图/几何断言才看得见。
- **定位铁律**：`#app` 内一律 `position:absolute`，禁止 `fixed`。**本阶段的 6 个弹窗全部 portal 到 `document.body` 且 `fixed` 视口居中**（W1 起的既存行为，规格 §7.1「弹窗群（Portal 到 body）」）——**不要**改成 `container=#app`，那是另一套定位模型（见 `2026-09-28-modal-inventory.md` §0 最后一条）。

## 已裁决的规格偏差（执行时按此为准，不得再议）

1. **`AppModal` 是组合壳，不新造原语**：它内部用 `ui/dialog` 的 `Dialog` / `DialogContent` / `DialogHeader` / `DialogTitle` / `DialogDescription`，`DialogContent` 一律传 `showCloseButton={false}`，自绘头部关闭钮（`Button variant="ghost" size="icon-sm"` + lucide `X`）。理由：10 个弹窗现状都是「自绘 × + `showCloseButton={false}`」，官方 `showCloseButton` 是 `absolute top-4 right-4` 的浮角钮，与「头部有新建/临时添加动作钮」的现行布局冲突；id 契约（`#close-*`）也必须保留。
2. **宽度令牌定为 6 档**：`sm=520 / md=640 / lg=720 / xl=820 / 2xl=1160 / full=1500`，沟槽**全部统一 48px**（现状有 32/42/48 三套）。这些值覆盖了现存 10 档里的 6 个；S5/S6 迁移时按最近档收敛（760→`lg`、860→`xl`、980→`2xl`）。**内置详情保留 720**（`w1c1` 脚本断言 `width === '720px'`，且提示词预览需要宽度），故 `lg=720` 这个档必须存在，不能把 720 并进 640/820。
3. **高度只有两种策略**：`height="auto"` = `max-h-[min(760px,calc(100vh-48px))] overflow-auto`；`height="fixed"` = `h-[min(760px,calc(100vh-48px))]` + `grid grid-rows-[auto_minmax(0,1fr)]`（头部一行 + 内容一行，内容行自己滚动）。**外部模型弹窗现状是全库唯一无高度上限**（内容可超视口）→ 本阶段按 `auto` 补上。
4. **不做 `footer` 槽**：本阶段 6 个弹窗的提交钮都在各自的 `<form>` 内（或没有底部栏），`footer` 只有 S5 的群模板 / S6 的编排需要。留到那时按加法方式补 prop，本阶段不预埋无人使用的 API。
5. **不做 `portal.container` / `closeOn` 透传**：前者是「弹窗限定在浮窗内」才需要（本阶段全部保持 body 视口居中，偏差 0 的既存行为）；后者服务「背板不关/Escape 不可关」的群模板与编排（S5/S6），本阶段 6 个弹窗全是默认关闭语义。
6. **搜索/表单控件改用官方 `Input` / `Textarea` 原语，`<select>` 保持原生**：现状弹窗里的裸 `<input>`/`<textarea>` 靠 legacy 全局 `input{height:36px;…}` 塑形，弹窗迁移后不应再依赖它 → 换 `ui/input`（h-9 官方默认）与 `ui/textarea`。`<select>` 不换 Radix `Select`（会改键盘/取值行为，S3 的 RolePanel 已定同例）。原生 `select` 的框体视觉由新增的 utilities 提供，并在 T3 记录其 legay 来源。
7. **成员抽屉内的提示词详情弹窗一并迁移**（`RolePanel.tsx:335-345`）：它属于人员族表面，且现状有两个 bug——`template-detail-modal` 的意图宽度 720px 被原语基类 `sm:max-w-lg` 钳成 512px（少了 `max-w-none`）、靠 `aria-describedby={undefined}` 压 Radix 警告。迁到 `AppModal`（`lg` + 自绘关闭钮 `id="close-role-prompt-detail"`）后两者自然消失。`#role-prompt-detail-title` 保留（`RolePanel.test.tsx:107-121`、`screenshot-p3-acceptance.mjs:236` 在用）。
8. **AlertDialog 不动**：5 个确认框继续用原语（`2026-09-28-modal-inventory.md` §4 已裁定），本阶段只保证它们的触发与文案路径不受影响。
9. **M-3（站点菜单分层语义）本阶段无动作**：S3 记账里那条讲的是**成员抽屉成员卡上的 Radix 下拉站点菜单**（模态菜单让非模态抽屉层 `pointer-events` 失效），本阶段不碰 RolePanel 的站点菜单；添加人员弹窗的站点选择是**复选框 label**（不是菜单），保持现状，由 T4 的几何/取色断言兜住。
10. **`.chat-create`（快速建群原位表单）不在本阶段**：它已在 2026-09-28 修复批次里退出 legacy 绝对定位、成为侧栏流内表单——它不是弹窗，不纳入 `AppModal`。

```tsx
const SIZE_CLASS: Record<AppModalSize, string> = {
  // 沟槽统一 48px（现状 32/42/48 三套并存，见 2026-09-28-modal-inventory.md §5.1）
  sm: 'w-[min(520px,calc(100vw-48px))]',

  lg: 'w-[min(720px,calc(100vw-48px))]',
  xl: 'w-[min(820px,calc(100vw-48px))]',
  '2xl': 'w-[min(1160px,calc(100vw-48px))]',
  full: 'w-[min(1500px,calc(100vw-48px))]',
}
const HEIGHT_CLASS = {
  auto: 'max-h-[min(760px,calc(100vh-48px))] overflow-auto',
  fixed: 'h-[min(760px,calc(100vh-48px))] overflow-hidden',
}
```

`DialogContent` 的 className 组装顺序（**每个类都从 prop 走 twMerge**，不靠输出顺序）：

```tsx
className={cn(
  'flex flex-col gap-0 p-0 rounded-lg bg-popover',   // 覆盖基类 gap-4 p-6 bg-background
  'max-w-none sm:max-w-none',                        // 抵掉基类 max-w-[calc(100%-2rem)] sm:max-w-lg
  SIZE_CLASS[size], HEIGHT_CLASS[height],
  height === 'fixed' ? 'grid grid-rows-[auto_minmax(0,1fr)]' : '',
  contentClassName,
)}
```

头部与内容：

