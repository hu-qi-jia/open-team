# S3 面板换血（成员抽屉 / 笔记浮卡 / 画布宿主）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把成员抽屉（RolePanel）换成 shadcn `Sheet`、笔记浮窗（NotesPanel）换成 shadcn `Card`、画布宿主（CanvasPortal）的尺寸规则 utilities 化，并清偿 S2 终审挂账的 S3 项。

**Architecture:** 继续绞杀式迁移：在既有 React 组件内做「原语接线 + 样式换血」，行为、id 契约、store/appState 链路、几何钩子（拖拽/缩放）逐条保留；每个表面迁移的同一 commit 内删除 legacy.css 中该表面的规则族。本阶段新增两条硬纪律（下述 Global Constraints）：①覆盖官方原语类名一律走 `className` prop（twMerge 去重），不靠声明顺序；②`forceMount` 常挂载的 Radix 组件不得依赖 `animate-in/out` 的终态。

**Tech Stack:** React 19 + Tailwind v4（`tw-animate-css`）+ shadcn/ui（new-york / zinc，本地 `src/teamPage/ui/components/ui/` 原语，`radix-ui@^1.6.7` 统一包）+ vitest + @testing-library/react。

**Spec:** `docs/superpowers/specs/2026-09-28-shadcn-ui-rebuild-design.md`（§4.7 面板、§6 组件映射表、§7.1 DOM 树、§7.4 阶段表 S3 行、§9:224「弹窗叠层：保持现有『逐层关闭』语义…不得改 Radix 层级参数以外的行为」——「行为不变」是 §4 各小节的措辞，§9 是「边界与错误处理」）。计划与规格冲突时以本计划的「已裁决的规格偏差」为准（该节是规格与现状冲突的裁定结果，执行时不得再议）。

## Global Constraints

- **样式基准**：shadcn 官网（new-york / zinc）为准；圆角只用 `rounded-md`(8px) / `rounded-lg`(10px) / `rounded-xl`(14px)（`xl` 仅浮窗外壳；菜单/命令项 `rounded-sm` 是官方做法，不算违规）。
- **零新依赖**：不新增任何 npm 包；只用已有 ui 原语（sheet / card / avatar / badge / button / empty / dropdown-menu / dialog / alert-dialog / tooltip）。
- **覆盖官方原语**：凡要改官方原语自带的类，**必须**把类写进该原语的 `className` prop（`cn()` = twMerge，同组后者胜）。禁止「子元素自带类名 + 靠 Tailwind 输出顺序取胜」——`.absolute` 与 `.fixed` 之类同组类谁生效由 dist 里的规则顺序决定，S2 已因此丢过两条 utility。
- **定位铁律**：`#app` 内一律 `position:absolute`，禁止 `fixed`（浮窗拖拽/缩放会剥离 `#app` 的 transform）。RolePanel 在 `#app` 内 → 走 portal(container=`#app`) + `absolute`；NotesPanel 在 `#app` **外**（`App.tsx:61`）→ 保留 `fixed`（视口贴边是既存行为，规格 §7.1 树明示）。
- **id/类契约逐字保留**：`#role-summary`、`#role-list`、`#add-role-form`、`#role-template-select`、`#open-gemini-login`、`#close-people-drawer`、`#role-prompt-detail-title`、`#notes-panel`、`#notes-drag-handle`、`#close-notes-panel`、`#chat-note-tab`、`#global-note-tab`、`#note-bold`/`-italic`/`-strike`/`-bullet-list`/`-ordered-list`/`-undo`/`-redo`、`#notes-editor`、`#notes-resize-handle`、`#orchestration-stage-canvas`；类 `.role-panel`(+`open`)、`.role-card`(+`active`)、`.role-avatar`、`.role-meta`、`.site-pill*`、`.role-site-menu`、`.role-site-option`、`.notes-panel`(+`open`/`dragging`/`resizing`)；属性 `data-role-prompt-detail` / `data-role-refresh` / `data-role-delete` / `data-note-scope`。
- **className 模板串纪律（v4.3.3 实测）**：类名紧贴 `${` 会被 Tailwind 扫描器**静默丢弃**。S3 触及的文件本次全部清扫：`RolePanel.tsx:164`（`shadow-2xl${`）、`RolePanel.tsx:329`（`transition-colors${`）、`NotesPanel.tsx:213/221`（`hover:text-foreground${`）。改写模板串时**每个** `${` 前留空格；T5 用 dist 复检。
- **legacy 清偿纪律**：读规则 → 把视觉值翻成 utilities → 同一 commit 删规则 → T5 取色/几何复拍验证。**共享族不得随本阶段删除**：`.notes-editor`（8 条，与 AllNotesModal 共用）、`.note-tool-btn`(3)/`.note-toolbar`/`.note-toolbar-spacer`（同上）、`.all-note-*`、`.tiny`、`.reference-box`、`.mention-shortcut`、`.section-title`、`.site-pill*`、`.role-tone-*`（后两者 T4 搬去 components 层，不是删）。
- **门禁**：每任务 `npm run typecheck` + 触及的测试文件 + `npm run build` 全绿才算完成。已知既有失败豁免：openteamcli 相关 ×2（模块导入 SyntaxError）、extensionConfig 路径分隔符 ×1、QuickCreateChat 4 条 `css-syntax-error` minify 警告。
- **禁令**：禁止 git worktrees、禁止 junction `node_modules`、禁止并行派发多个实现子代理；评审者只读。
- **runtime 不动**：`iframeHost`/`sendWithReconnect`/编排 runtime/`notesBridge`/`useFloatingPanelGeometry` 一律不改。

## 已裁决的规格偏差（执行时按此为准，不得再议）

1. **RolePanel 留在 `#app` 内渲染**。§4.7 与 §7.1 的句子「两者都是覆盖层，仍在 `#app` 之外渲染」对 RolePanel **不成立**：它现状是 `#app` 的直接子级（`App.tsx:58`），靠 `position:absolute` 贴浮窗右缘。移到 `#app` 外并 `fixed` 到视口会**脱离可拖拽浮窗**，产品语义错误。→ 实现为 `<Sheet modal={false}>` + `<SheetPortal container={#app元素} forceMount>` + `absolute` 内容（`#app` 的 transform 让 absolute 相对它定位）。NotesPanel 维持 `#app` 外 + `fixed`（规格原意，不动）。
2. **无 Switch**。§4.7「连接状态（受控 Switch 语义与现状一致）」前提不成立：RolePanel 无开关，仓库也没有 `ui/switch.tsx`。按 S2「附件按钮」同例，不新发明控件 → 连接状态仍用 `Badge variant="outline"`（对齐 `ChatHeader.tsx:123` 既有写法）+ `size-1.5 rounded-full` 状态点复现 `::before` 圆点。
3. **编排入口为 no-op**。§4.7「编排入口按现状保留」＝现状**没有**编排入口（编排入口在 ChatHeader），不新增。
4. **「添加成员」目标不变**：§4.7 写「→人员库」，现状是 `services.uiBus.emit('open-add-person')` → `AddPersonModal`。保持现状（人员库 `PeopleLibraryModal` 归 S4）。
5. **宽度取 340px + 保留护栏**：`w-[340px] max-w-[calc(100%-54px)] sm:max-w-none`（compact 档 `#app` 可窄于 340px；54px 让用户仍能点到工作区以触发外点关闭）。
6. **不用 Radix Tabs**。§4.7 §6 的「Tabs(范围)」只按**视觉**对齐（照抄 `ui/tabs.tsx` 的 TabsList/TabsTrigger 类名到既有 `role="tablist"` + `active` 类标记上）。理由同 S2 的提及面板裁决：编辑器不是 TabsContent，Radix Tabs 会改变既有键盘/焦点行为。
7. **NotesPanel 根元素由 `aside` 变为 `Card`**（`div[data-slot=card]`），补 `role="complementary"` + 既有 `aria-label` 保持地标语义不变。`backdrop-filter: blur(24px)` 一并去掉：新底色 `bg-card` 不透明，模糊是死效果。
8. **官方 Sheet 的 `animate-in/out` 不采用**：`tw-animate-css` 的 `animate-out` 退场动画 fill 不保留终态，而 `forceMount` 下关闭态元素常驻 → 首帧会播一次「抽屉滑走」且终态回弹。改用 `data-[state=closed]:translate-x-full` + `transition-transform` 过渡（等价于 legacy 的 0.18s 位移），并用 `[animation:none]!` 关掉官方动画类。
9. **CanvasPortal 只做宿主容器**：`#orchestration-stage-canvas` 的 `width/height/min-height` 迁 utilities（类名保留，可能被 runtime 查询）。画布内部（x6 节点/边）与 `.orchestration-workspace` 的边框/渐变归 S6「画布样式微调」。
10. **RolePanel 根元素由 `aside` 变为 `Dialog.Content`**（`div[role="dialog"]`，Radix 提供 aria 语义，`SheetTitle`/`SheetDescription` 提供无障碍名）。选择器 `aside.role-panel` → `.role-panel`（3 处测试 + `scripts/screenshot-p4d-acceptance.mjs` 4 处）。
11. **抽屉的层叠保持 legacy 次序（T2 评审 I-1 的裁定；已按 `9e8d646` 落地）**：官方 `SheetContent` 基类自带 `z-50`，会让抽屉盖住 `#app` 右上角的浮窗铬件（`.floating-toolbar` `z-index:12`，`legacy.css:75-95`）与窗口缩放把手（`.window-resize-handle` `z-index:8`，`globals.css`）——而退役的 legacy `.role-panel` 是 `z-index:4`，三枚窗控钮与右缘/右下把手原本浮在抽屉之上、始终可点。规格 §9:224「弹窗叠层：保持现有『逐层关闭』语义…」优先 → 抽屉 className 显式钉 `z-4`（v4 原生接受裸数字，dist 已生成 `.z-4{z-index:4}`；与退役的 legacy `.role-panel` 同值）：语义是「在应用内容之上、在窗控与窗口把手之下」。T5 的 s3-3/s3-5 各补一条断言：抽屉打开时 `document.elementFromPoint(<窗控钮中心>)` 命中该钮本身（而非抽屉）。— 若错，代价是抽屉被 11px 窗控钮与 4px 把手压住（与 legacy 观感一致），回退为 `z-50` 即可。
